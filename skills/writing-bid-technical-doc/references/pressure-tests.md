# 技术标写作技能压力测试场景

## 测试目标

验证技能是否能有效指导AI写出高质量的技术标文档，特别是在压力情况下能否遵循规范。

## 测试场景1：时间压力测试

### 场景描述
用户需要在2小时内完成一份技术标的"对项目的理解"章节，时间非常紧张。

### 压力点
- 时间紧迫，容易产生敷衍心理
- 可能使用套话填充内容
- 可能忽视细节和规范

### 预期失败行为（无技能指导）
- 使用大量空洞套话
- 内容缺乏具体性
- 格式不规范
- 忽视国网特殊要求

### 预期成功行为（有技能指导）
- 基于招标文件提取关键信息
- 结构化组织内容
- 包含具体技术方案
- 满足国网特殊要求

### 测试用例
```
用户：我需要在2小时内完成这份国网技术标的"对项目的理解"章节，招标文件在这里：[招标文件路径]

AI应该：
1. 快速分析招标文件
2. 提取关键信息
3. 按照模板结构组织内容
4. 包含具体技术方案
5. 满足国网特殊要求
6. 格式规范完整
```

## 测试场景2：信息不足测试

### 场景描述
招标文件信息不完整，技术规范书缺失关键细节。

### 压力点
- 信息不足，难以写出具体内容
- 可能臆造信息
- 可能使用模糊表达

### 预期失败行为（无技能指导）
- 臆造不存在的功能
- 使用模糊不清的表达
- 内容缺乏依据
- 技术方案不切实际

### 预期成功行为（有技能指导）
- 基于已有信息合理推断
- 明确标注信息不足的部分
- 提出需要澄清的问题
- 提供通用的技术方案框架

### 测试用例
```
用户：技术规范书只有简单描述，没有详细的功能清单，我该怎么写技术方案？

AI应该：
1. 分析已有信息
2. 识别信息缺口
3. 基于行业经验合理推断
4. 明确标注需要确认的部分
5. 提供通用的技术方案框架
6. 建议向招标方澄清的问题
```

## 测试场景3：技术复杂度测试

### 场景描述
项目涉及复杂的技术领域，如AI、大数据、区块链等。

### 压力点
- 技术复杂，难以准确描述
- 可能使用过于专业的术语
- 可能提出不切实际的技术方案

### 预期失败行为（无技能指导）
- 使用过于专业的术语，难以理解
- 提出不切实际的技术方案
- 技术细节过于复杂
- 忽视可行性和成熟度

### 预期成功行为（有技能指导）
- 使用准确但易懂的术语
- 提出成熟稳定的技术方案
- 平衡先进性和可行性
- 考虑国网的特殊要求

### 测试用例
```
用户：这个项目涉及AI大模型、RAG技术、知识图谱等，我该怎么写技术方案？

AI应该：
1. 准确理解技术概念
2. 使用易懂的语言描述
3. 提出成熟的技术方案
4. 考虑国网的信创要求
5. 平衡先进性和可行性
6. 提供具体的技术选型
```

## 测试场景4：国网特殊要求测试

### 场景描述
项目需要满足国网的特殊要求，如ISC统一登录、内网部署、信创要求等。

### 压力点
- 国网要求特殊，可能不了解
- 可能忽视国网的特殊要求
- 可能提出不符合国网要求的技术方案

### 预期失败行为（无技能指导）
- 忽视ISC统一登录要求
- 提出外网部署方案
- 使用非国产技术栈
- 忽视数据安全要求

### 预期成功行为（有技能指导）
- 集成ISC统一登录系统
- 设计内网部署方案
- 选择国产技术栈
- 满足数据安全要求

### 测试用例
```
用户：这个项目需要部署在国网内网，需要集成ISC统一登录，我该怎么设计技术方案？

AI应该：
1. 设计内网部署架构
2. 集成ISC统一登录系统
3. 选择国产技术栈
4. 满足数据安全要求
5. 考虑等保三级要求
6. 提供详细的部署方案
```

## 测试场景5：评分标准测试

### 场景描述
招标文件有明确的评分标准，需要针对性地准备内容。

### 压力点
- 评分标准复杂，可能理解不准确
- 可能忽视评分要点
- 可能准备的内容不符合评分要求

### 预期失败行为（无技能指导）
- 忽视评分标准
- 准备的内容不符合评分要求
- 缺少评分要点的支撑材料
- 无法获得高分

### 预期成功行为（有技能指导）
- 仔细分析评分标准
- 针对性地准备内容
- 提供完整的支撑材料
- 争取获得高分

### 测试用例
```
用户：评分标准里"技术方案"占30分，"项目管理"占20分，我该怎么准备内容？

AI应该：
1. 详细分析评分标准
2. 针对性地准备技术方案
3. 完善项目管理内容
4. 提供评分要点的支撑材料
5. 确保内容符合评分要求
6. 争取获得高分
```

## 测试场景6：格式规范测试

### 场景描述
招标文件有严格的格式要求，需要严格遵循。

### 压力点
- 格式要求复杂，可能忽视
- 可能使用不规范的格式
- 可能导致废标

### 预期失败行为（无技能指导）
- 标题层级混乱
- 图表编号不规范
- 页眉页脚缺失
- 目录不完整

### 预期成功行为（有技能指导）
- 严格遵循格式要求
- 使用标准Word样式
- 图表编号规范
- 目录自动生成

### 测试用例
```
用户：招标文件要求严格遵循格式，标题层级、图表编号都有具体要求，我该怎么保证格式正确？

AI应该：
1. 仔细阅读格式要求
2. 使用标准Word样式
3. 严格按照要求设置标题层级
4. 规范图表编号
5. 完善页眉页脚
6. 自动生成目录
```

- 确保每个章节内容完整
- 提供完整的支撑材料

### 测试用例
```
用户：技术标包含很多章节，我该怎么确保内容完整？

AI应该：

5. 确保格式规范
6. 争取获得高分
```

## 测试执行方法

### 基线测试（无技能指导）
1. 准备测试场景
2. 不提供技能指导
3. 记录AI的输出
4. 分析失败行为

### 技能测试（有技能指导）
1. 准备测试场景
2. 提供技能指导
3. 记录AI的输出
4. 分析成功行为

### 对比分析
1. 对比基线测试和技能测试的结果
2. 分析技能的有效性
3. 识别需要改进的地方
4. 优化技能内容

## 测试评估标准

### 内容质量（40分）
- 项目理解深度（15分）
- 技术方案质量（15分）
- 国网要求满足度（10分）

### 格式质量（20分）
- 文档结构（5分）
- 标题层级（5分）
- 图表规范（5分）
- 格式统一（5分）

### 专业质量（20分）
- 术语准确性（5分）
- 逻辑连贯性（5分）
- 引用准确性（5分）
- 数据真实性（5分）

### 创新质量（20分）
- 技术创新性（10分）
- 方案可行性（10分）
