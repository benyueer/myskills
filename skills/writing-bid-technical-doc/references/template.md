# 技术标模板结构

## 输出格式要求

**最终交付物必须是单独的 .docx 文件（Word文档）**，格式规范，符合招标文件要求。

## 评审标准分析

## 三个关键文件前置理解

开始撰写正式正文前，必须先理解三个关键文件：

| 文件 | 必须提取的信息 |
| --- | --- |
| 招标公告 | 项目名称、招标编号、采购单位、包件信息、资格条件、关键日期 |
| 招标文件 | 评标办法、评分标准、投标格式、否决条款、签章要求、合同和验收约束 |
| 技术规范书 | 功能需求、非功能需求、架构要求、集成对象、部署要求、工作量、技术标准、交付物 |

所有招标信息必须从这三个文件中提取。未理解三类文件前，不得直接撰写正式章节；材料缺失时先输出缺口和待确认问题。

### 服务方案评审要素（以招标文件实际分值为准）

在撰写技术文件之前，必须先分析本标的招标文件第三章“评标办法”，提取其中的“技术评审标准”，再找到技术评审标准里的“服务方案”评审要素。后续必须用该“服务方案”评审要素评估第六章“对项目的理解”；只有达到“优”这一等级才视为可接受方案。下表是常见维度示例，不得把示例分值或维度当成固定规则：

| 评审维度 | 说明 | 在"对项目的理解"中的体现 |
|---------|------|------------------------|
| **先进性** | 技术方案是否采用先进技术 | 技术方案设计 - 关键技术选型 |
| **创新性** | 方案是否有创新点 | 技术方案设计 - 创新点说明 |
| **可操作性** | 方案是否切实可行 | 项目特点、关键点、难点 - 难点及应对策略 |
| **技术性** | 技术方案的专业程度 | 技术方案设计 - 总体技术架构 |
| **经济性** | 方案的经济效益 | 项目目标与价值 - 项目价值分析 |
| **风险** | 风险识别和应对措施 | 项目特点、关键点、难点 - 难点及应对策略 |

## 文档结构

```
技术文件
├── 技术偏差表
├── 专项投标文件
│   ├── 业绩文件
│   ├── 项目团队情况
│   ├── 对项目的理解 (重点章节)
│   ├── 履约能力及质量保证措施
│   ├── 服务承诺
│   └── 技术评分标准支撑材料
├── 资质业绩凭证单
└── 技术规范书规定的其他文件
```

## 格式要求

### 标题样式
- 一级标题：6.1 对本招标项目的理解与认识
- 二级标题：6.1.1 项目背景与现状
- 三级标题：(1) 行业背景分析

### 图表编号
- 图：图1、图2、图3...
- 表：表1、表2、表3...

### 页眉页脚
- 页眉：项目名称
- 页脚：页码

### 目录
- 自动生成目录
- 包含三级标题

## 常见错误

### ❌ 格式错误
- 标题层级混乱
- 图表编号不规范
- 页眉页脚缺失

### ❌ 内容错误
- 内容空洞
- 技术方案不切实际
- 忽视国网特殊要求
- **未对齐评审标准**

### ❌ 引用错误
- 引用不准确
- 数据不真实
- 术语使用错误

## 使用说明

1. **首先分析招标文件中的评审标准**，找到"服务方案"评审要素
2. 根据评审标准，选择需要的章节
3. 使用模板结构，填充具体内容
4. **围绕评审维度（先进性、创新性、可操作性、技术性、经济性、风险）组织内容**
5. 确保内容符合项目实际需求
6. 检查格式是否符合要求
7. 验证内容是否完整准确
